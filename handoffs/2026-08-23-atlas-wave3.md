## What you asked → what exists

1. **Top bar / tabs.** 40 px bar; Live · History · Settings actually switch (the Home grid was overriding
   the `hidden` attribute); the tab lives in `location.hash` so reloads keep it.
2. **Atlas Engine.** Hand-rolled Canvas: core disc, thin ring, **96 radial bars** driven by 24 live
   frequency bands from the wake loop (`/signal`), state colours (ASLEEP grey breathing, LISTENING purple,
   THINKING rotating arcs + sweep, SPEAKING pulsing core), no glyph/letter/diamond. Draw cost measured
   live at **0.15 ms/frame** average. Research verdict: no permissive radial library accepts pushed bands
   (audioMotion is AGPL and needs Web Audio), so it is bespoke.
3. **History / Settings.** History lists terminal jobs with result fetch (paired bearer) and cancel on
   active ones; Settings shows voice/wake, **live audio devices**, MCP servers + tool counts, launcher
   availability, config paths.
4. **Overhead.** Worker **600 MB → 308 MB** idle, **13 s → 3.7 s** to `/state`: lazy Anthropic/ElevenLabs
   imports, only the configured wake model loaded, Deepgram Flux end-of-turn instead of LiveKit's extra
   local model. Audit with method + tables: `docs/audits/2026-08-23-overhead.md`. WebView2 (~400 MB across
   Chromium helpers) is the window itself and is unchanged.
5. **Bluetooth / device follow.** Mic and speaker now follow the Windows default device: the installed
   LiveKit supports reopening the mic in-process (`set_microphone_enabled(..., device=)`), the wake-word
   stream reopens on the new device at its native rate and resamples to 16 kHz (HFP-capable), TTS output
   already followed. Exit code 21 + in-place restart remains only for unresolvable devices. Live check:
   `/state.audio` = Intel mic array / "Headphones (AirPods)", both `following: true`.

## Review and what it changed

- Sonnet independent verifier: PASS (spec clauses quoted line by line, no dead references, no secrets).
- Codex `gpt-5.6-sol` adversarial review (read-only, xhigh): 21 findings; 17 accepted and fixed by three
  workers, 4 rejected as product choices (file-name taint, forwarding Daniel's own transcript after a read,
  the folder line in background prompts, the kb root in `file_roots`). Fixed: confirmation accepts only
  closed affirmatives (every token must be an affirmative, a filler, or a word of the pending action — "yes it
  was great" is no longer a yes); `confirm`/`cancel_pending` are host-only (the model never sees them); any
  pending action blocks new proposals; the readback summary lists every field (oversized proposals are
  refused); the host persists a confirmed outcome before narrating and says *why* on failure; the UI bearer
  has an expiry and a re-pair path; `wake_model` is in `/state`; the model client warms off the turn path;
  both audio directions keep being watched when their first probe fails; wake-stream reopen retries with a
  failure callback; LiveKit capture (24 kHz) is capability-tested before a follow is declared; device flaps
  coalesce instead of stopping Atlas; **audio restarts no longer kill background Claude sessions** (the Job
  Object allows breakaway and `claude --bg` breaks away); OneDrive cloud placeholders are allowed and reads
  run off the event loop; `hey_jarvis` is tried when the configured wake model fails.
- Live smoke defects found and fixed after the review: oversized files returned 16 KiB into the turn and
  hit the budget (now a preview + `launch_work` with per-call timeouts); the poller could read `claude logs`
  a beat before the result frame landed (status-first polling + refetch on done); MCP reports tool errors as
  text (now a real error, with the bounded reason passed through); `to: "me"` is rejected by Gmail (host maps
  me/myself to your account); MCP sessions are closed from the task that opened them.
- Residual, documented: Dart-style integration tests for real Windows audio/Job-Object behaviour are not
  automated; the `hey_jarvis` fallback model is fetched on first use (not bundled offline).
