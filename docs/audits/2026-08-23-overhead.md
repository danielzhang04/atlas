# Atlas worker overhead audit

Date: 2026-08-23.

Platform: Windows.

Interpreter: `C:\Users\danie\Atlas\.venv\Scripts\python.exe`.

The target is at most 350 MB idle working set and at most 8 seconds from launch until `/state` answers.

## Method

The import profile used `python -X importtime -c "import worker.app"`.

The isolated import probe launched one fresh interpreter per module.

The probe read RSS through `psutil.Process().memory_info().rss` and retained a ctypes `GetProcessMemoryInfo` fallback.

The worker probe launched `python -m worker.app console --text` and `python -m worker.app console` without a window.

The worker probe parsed the emitted `ATLAS_UI` URL and issued `GET /state` before stopping the clock.

The worker probe sampled the actual Python worker and its process tree separately.

The full-audio after sample waited eight seconds after `/state` so the wake model had finished loading.

The measurement-only `LOCALAPPDATA` pointed inside the worktree because the sandbox does not permit the configured database path.

## Before

The supplied production baseline was 600 MB working set and about 13 seconds to `/state`.

The reproducible pre-change text-console sample reached `/state` in 4.512 seconds.

The pre-change text-console worker used 463.3 MB.

The pre-change text-console process tree used 475.1 MB.

The text path excludes the OpenWakeWord sessions, so it isolated the LiveKit and service-construction overhead.

The pre-change text worker was 263.3 MB larger than the after text worker.

## Cuts

`worker.wakeword.load_model` already passed exactly one configured model in `wakeword_models` and selected `inference_framework="onnx"`.

The real wake-model probe loaded only `hey_atlas.onnx`, `melspectrogram.onnx`, and `embedding_model.onnx`.

The real wake-model probe reported only the `hey_atlas` prediction key.

No bundled wake models were loaded.

The OpenWakeWord ONNX sessions already set both intra-op and inter-op thread counts to one, so no process-wide thread environment override was added.

ElevenLabs now imports only inside the ElevenLabs voice branch.

The configured Deepgram voice does not import ElevenLabs.

The default Anthropic client now imports and constructs on the first conversational turn.

An explicitly supplied client remains unchanged for tests and alternate composition.

The LiveKit session now uses Deepgram Flux STT end-of-turn events instead of allocating the redundant default local semantic turn model.

Silero VAD remains loaded for voice activity and interruption behavior.

MCP connection and `WorkManager.run` remain scheduled as background tasks and are not awaited before `/state` starts.
